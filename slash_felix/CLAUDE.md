## What this is

This directory (`slash_felix`) is one of two sibling board targets in the parent git repo
(`porting_slash`, one level up), the other being `../slash_vek280`. The repo is a Vivado
IP-Integrator porting effort: taking the ESnet **SLASH** SmartNIC shell (hw_discovery, cmd_queue,
shell_utils_uuid_rom, axi4_full_passthrough IP + block-design topology) and porting it from the
VEK280 eval board (`slash_vek280`, part `xcve2802-vsvh1760-2MHP-e-S`) to the **FELIX** PCIe card
(`slash_felix`, part `xcvp1552-vsva3340-2MHP-e-S`). Both boards are Versal devices; the CIPS
(Control, Interfaces & Processing System) script here is derived from the VEK280 one but retargeted
to the new part and NoC/DDR topology.

There is no HDL/software build here in the conventional sense — the deliverable is a Vivado block
design (`myproj/project_1.xpr` + the `felix_cips` BD) constructed entirely via Tcl scripts driving
the Vivado IP Integrator API (`create_bd_cell`, `connect_bd_intf_net`, etc.).

## Repo layout

- `am_felix_cips.tcl` — generated-style BD script (Vivado "write_bd_tcl" output, hand-extended).
  Creates the project (if absent), registers `iprepo` as a local IP repo, and builds the
  `felix_cips` block design: CIPS (`versal_cips`), PCIe management reset hierarchy
  (`pcie_mgmt_pdi_reset`), clock/reset hierarchy (`clock_reset`), and `base_logic` (hw_discovery +
  uuid_rom + cmd_queue behind a smartconnect, PCIe config/mgmt path).
- `am_felix_noc.tcl` — run **after** the cips script. Adds `axi_noc_cips` (CIPS↔fabric NoC, 4 SI /
  1 MI / 8 NSI / 1 NMI) and `axi_noc_ddr4` (DDR4-2666, 72-bit ECC memory controller) as bare cells
  with bandwidth/aperture/clock CONFIG set, but **no connections** — those are wired manually in
  the Vivado GUI afterward.
- `am_felix_service_layer.tcl` — run **after** the noc script. Builds the `service_layer`
  hierarchy (kernel virtual-memory NoC paths `noc_virt_0..3`, QDMA bridge path `noc_virt_4`,
  8× `sl2noc_0..7` paths to DDR4, `axi4_full_passthrough` and `axi_register_slice` fan-out) with
  full internal wiring, matching the SLASH reference topology minus DCMAC/HBM. Idempotent: it
  deletes any hierarchy/cells it previously created before rebuilding, so it's safe to re-run.
  External ports (`SL2NOC_*`, `M_VIRT_*`, `S_VIRT_*`, `S_QDMA_SLV_BRIDGE`, `M_QDMA_SLV_BRIDGE`,
  `S_AXILITE_INI`, `M_AXILITE_MGMT`, `service_clk`, `service_resetn`) are left unconnected — wired
  to `axi_noc_cips` / `cips` manually in the GUI.
- `iprepo/` — custom (non-catalog) Xilinx-format IP used by the SLASH shell, checked in with
  `component.xml` + `hdl/` + `xgui/` per IP:
  - `hw_discovery_v1_0` — PCIe VSEC-based hardware discovery / BAR layout ROM.
  - `shell_utils_uuid_rom_v2_0` — shell UUID ROM utility.
  - `cmd_queue_v2_0` — AXI command queue (used as `gcq_m2r`, management-to-register command path).
  - `axi4_full_passthrough` — currently untracked/in-progress (see `git status`); used in the
    service layer as pass-through fan-out stages.
- `myproj/` — Vivado working project output (`.xpr`, `.gen`, `.cache`, `.srcs`, `.sim`, `.hw`,
  `.ip_user_files`). Entirely generated by the scripts above; not checked into git.
- `vivado*.log` / `vivado*.jou` / `*.backup.log/.jou` / `*.str` — Vivado session logs/journals/state
  left over from interactive runs; not checked into git, safe to ignore or clean up.

## Running the scripts

All scripts must be run from within this directory (they resolve paths relative to
`[info script]`) using Vivado **2025.1** (the cips script checks this and errors on a version
mismatch):

```tcl
# from a shell, batch mode:
vivado -mode batch -source am_felix_cips.tcl
vivado -mode batch -source am_felix_noc.tcl            # after cips
vivado -mode batch -source am_felix_service_layer.tcl   # after noc

# or from the Vivado Tcl console, in order:
source am_felix_cips.tcl
source am_felix_noc.tcl
source am_felix_service_layer.tcl
```

`am_felix_cips.tcl` creates `myproj/project_1.xpr` if it doesn't already exist — do not run it
against a directory that already has a different `myproj/project_1.xpr` you want to keep. The
other two scripts `open_project`/`open_bd_design` the existing project and BD, so they require the
cips script to have already run.

After the noc and service-layer scripts, the remaining top-level BD wiring (NoC↔service-layer,
NoC↔CIPS aperture, mgmt AXI routing) is done manually in the Vivado GUI — this is expected, not a
missing step in the scripts.

## Working with these Tcl files

- Preserve the `xilinx.com:ip:<name>:<version>` VLNV pins when editing — Vivado IP Integrator
  scripts are version-sensitive; bumping an IP's version generally requires regenerating the
  script section from a real Vivado session rather than hand-editing.
- Keep changes idempotent where the surrounding script already is (see the cleanup `foreach`
  block at the top of `am_felix_service_layer.tcl`) so scripts can be safely re-run against an
  existing BD during iteration.
- When comparing against the reference design, `../slash_vek280/am_vek280_cips.tcl` is the
  VEK280-targeted equivalent of `am_felix_cips.tcl` — useful for diffing part/BD differences
  between the two boards.
