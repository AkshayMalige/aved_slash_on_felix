## 0. Background: what SLASH is and how V80 wires it

SLASH turns a Versal card into a multi-tenant accelerator: user HLS kernels
are loaded at runtime via partial reconfiguration (DFX) without rebuilding or
re-flashing the board.

- **`static_region`** — programmed once, never changes. Owns everything that
  must survive a kernel swap: PCIe link (CIPS/CPM5), board management (AVED),
  NoC routing fabric, memory controllers. If any of this were reconfigurable,
  the host would lose the PCIe link on every kernel load.
- **`slash` + `service_layer`** — Block Design Containers (BDC); both are
  marked reconfigurable by `enable_dfx_bdc.tcl`
  (`CONFIG.ENABLE_DFX {true}`, `LOCK_PROPAGATE {true}`). They contain the
  kernel attach points and kernel↔memory plumbing. `v80++ link` splices user
  kernels into these at link time.

Mental model: **static_region = motherboard; slash + service_layer = the
swappable card.** Everything crossing the boundary goes over Versal NoC INI
links, which tolerate reconfiguration without extra gating logic.

### 0.1 V80 static_region internals (from top.tcl)

```
static_region
├── aved            = cips + base_logic + clock_reset   (board mgmt + PCIe)
├── noc             = axi_noc_cips + axi_noc_mc_ddr4_0/_1  (routing + memory)
├── virt_noc        = axi_noc_0..4   (INI retiming stages toward service_layer)
├── clk_rst_shell   = user-clock wizards + resets, mgmt-controllable
├── axi_noc_1       = QDMA slave-bridge return path (NSI→MI)
├── dcmac_noc       = 8× AXI-Stream NoCs               (DCMAC-only → skip)
└── dfx_decoupler_0 = gates the 64 HBM BLI ports        (HBM-only → skip)
```

**aved**: `cips` (CPM5, QDMA mode, PF0/1/2 dev IDs 50b4/50b5/50b6),
`base_logic` (`hw_discovery` = BAR layout discovery for the driver,
`uuid_rom` = shell identity, `gcq_m2r` = host-AMI↔RPU command queue,
`pcie_slr0_mgmt_sc` + `rpu_sc` smartconnects), `clock_reset`
(clk_wizard 300/500 MHz + 4× proc_sys_reset + `pcie_mgmt_pdi_reset` GPIO
hierarchy). V80's `rpu_sc` is NUM_MI=2 with `axi_smbus_rpu` (smbus:1.1) on
M01 — the FELIX version is correctly NUM_MI=1, **no SMBus**.

**axi_noc_cips (V80)**: 4 SI / 2 MI / 7 NMI / 24 NSI, plus the HBM controller
*integrated into this same cell* (`HBM_NUM_CHNL=16`, `NUM_HBM_BLI=64`,
64× `HBMxx_AXI` BLI pins). Full port map and the reason each connection exists:

| Ports | Connection | Why it exists |
|---|---|---|
| S00_AXI ← CPM_PCIE_NOC_0 | host PCIe → DDR4 | host DMA to card memory |
| S01_AXI ← CPM_PCIE_NOC_1 | host PCIe → everything (mgmt, DDR, HBM, clk regs) | management/BAR access path |
| S02_AXI ← PMC_NOC_AXI_0 | PMC → DDR4 | boot/flash-time memory access |
| S03_AXI ← LPD_AXI_NOC_0 | RPU/LPD → DDR4 | RPU firmware memory access |
| M00_AXI → aved/s_axi_pcie_mgmt_slr0 | → base_logic | host reaches hw_discovery/uuid/gcq (aperture 0x201_0000_0000 / 32M) |
| M01_AXI → aved/NOC_PMC_AXI_0 | back into CIPS PMC | host reaches flash/boot resources |
| M00–M03_INI → ddr4_0/ddr4_1 (2 INI each) | → memory controllers | the DRAM path |
| M04_INI → slash/S_AXILITE_INI | kernel AXI-Lite control | host writes kernel regs (0x202_0000_0000 / 16M) |
| M05_INI → service_layer/S_AXILITE_INI | service-layer control | 0x203_0000_0000 / 4M — same aperture the FELIX scripts already use |
| M06_INI → clk_rst_shell/S00_INI | clock/reset control regs | host-programmable kernel clocks (`v80-smi set-frequency`) |
| S00–S03_INI ← slash/M00–M03_INI | kernel DDR traffic in | kernels → DDR4 (spread over both channels) |
| S04–S11_INI ← slash/HBM_VNOC_INI_00..07 | **HBM only — skip** | |
| S12–S19_INI ← service_layer/SL2NOC_0..7 | kernel data in | matches FELIX SL2NOC_0..7 |
| S20–S23_INI ← service_layer/M_VIRT_0..3 | virtual-memory return → DDR4 | QDMA buffer traffic lands in DRAM |

**HBM**: no separate controller cell — it lives inside `axi_noc_cips` CONFIG.
Skipping HBM = simply never setting those CONFIG keys (already the case in
the FELIX `axi_noc_cips`). Also delete `hbm_ref_clk_0/1` ports.

**dfx_decoupler_0**: sits *only* on the 64 HBM BLI interfaces, because BLI
ports cross the DFX boundary as raw AXI and must be gated during
reconfiguration. INI-based paths (DDR, VIRT, AXI-Lite) need no decoupling —
the NoC handles it. **No HBM on FELIX ⇒ no dfx_decoupler needed at all.**

**DDR4 (V80)**: two controllers (`axi_noc_mc_ddr4_0/_1`), each
`CONTROLLERTYPE DDR4_SDRAM`, `NUM_MC=1`, `NUM_MCP=4`, **`NUM_NSI=2`**
(S00_INI = host traffic, S01_INI = kernel traffic — separate entry points),
x16 components, 72-bit, DDR4-3200AA, ECC scrub on. External ports:
`CH0_DDR4_0_x` + differential `sys_clk0_x`.

**QDMA slave-bridge loopback (static infrastructure, currently MISSING in
the FELIX design)** — how PL logic reaches the QDMA engine's AXI slave
bridge (descriptor/bypass path used by the driver):

```
slash/QDMA_SLAVE_BRIDGE_0 → virt_noc → service_layer/S_QDMA_SLV_BRIDGE
  → (register slices + axi4_full_passthrough inside service_layer)
  → service_layer/M_QDMA_SLV_BRIDGE → static_region/axi_noc_1 (NSI→MI)
  → axi_noc_1/M00_AXI → aved/NOC_CPM_PCIE_0   ← back into the CPM5
```

**virt_noc**: five plain INI→INI retiming NoCs between static_region and
service_layer. The FELIX design connects these paths more directly — fine.

**clk_rst_shell**: gives the host runtime control of user-kernel clock
frequencies. Optional for bring-up; needed later for `v80-smi set-frequency`.

### 0.2 What is already correct in the FELIX port (verified)

- `cips` CPM_PCIE1 config is a faithful match to V80's (QDMA, 32 GT/s, PF
  IDs/BARs identical). Only link width / GT bank changes (Gen5 x8 today; the
  board can do 2×8 on GTYP banks 102–105).
- `base_logic` matches V80 minus SMBus (rpu_sc NUM_MI=1). `clock_reset` and
  `pcie_mgmt_pdi_reset` match exactly.
- `service_layer` port set and internal chain topology
  (`axi_noc bridge → reg_slice → axi4_full_passthrough → reg_slice →
  noc_virt`) match the real service_layer.tcl exactly, minus DCMAC/QSFP
  (correctly excluded). `axi4_full_passthrough` is a plain pipeline stage —
  it has nothing to do with the DFX boundary.
- `axi_noc_ddr4` MC settings match the proven `step1_vp1552` config exactly:
  72-bit UDIMM, DDR4-2666V(19-19-19), 2-rank, ROWADDRESSWIDTH 17,
  MC_INPUTCLK0_PERIOD 5000 (200 MHz sys_clk).
- DCMAC/SMBus/HBM: nothing to delete — never built. Confirmed the real
  service_layer.tcl gates DCMAC behind `DCMAC0_ENABLED/DCMAC1_ENABLED` flags
  anyway.

### 0.3 Known gaps in the FELIX port (what the plan below fixes)

1. Orphaned `dfx_decoupler_0` in `static_region` — unneeded, delete.
2. QDMA slave-bridge loopback path absent (`axi_noc_1` equivalent +
   `NOC_CPM_PCIE_0` connection missing).
3. `service_layer/M_AXILITE_MGMT` + `S_AXILITE_INI` don't match the real
   shell's management topology (real service_layer has no M_AXILITE_MGMT;
   mgmt egress to base_logic comes straight from axi_noc_cips M00_AXI).
4. `axi_noc_ddr4` is NUM_NSI=1 — V80 splits host vs kernel traffic on
   separate INI ports (NUM_NSI=2).
5. Top-level wiring (CIPS↔NoC↔DDR↔service_layer) still unconnected.
6. No pin constraints / no implementation run yet.

## Phase A — finish the static shell (Vivado, current project)

Work in `myproj/project_1.xpr`, BD `felix_cips`. Do steps in order; each is
small and independently checkable. After every step: save, and re-run
`validate_bd_design` expecting only the *known-remaining* complaints.

### A1. Delete the orphaned dfx_decoupler_0
- `delete_bd_objs [get_bd_cells /static_region/dfx_decoupler_0]`
- Rationale: on V80 it exists only to gate the 64 HBM BLI ports across the
  DFX boundary. No HBM ⇒ nothing to gate. INI links don't need decoupling.
- Check: cell gone, no dangling nets.

### A2. Give axi_noc_ddr4 two INI entry points (host vs kernel traffic)
- On `/static_region/axi_noc_ddr4`: set `CONFIG.NUM_NSI {2}`.
- S00_INI = host-side traffic (from axi_noc_cips routes fed by
  S00–S03_AXI). S01_INI = kernel-side traffic (routes fed by SL2NOC/VIRT
  NSI ports).
- Both INI pins get `CONFIG.CONNECTIONS {MC_0 {read_bw {…} write_bw {…}}}`
  — start with 1000/1000 on each; tune later.
- On `/static_region/axi_noc_cips`: set `CONFIG.NUM_NMI {2}` (was 1) so it
  has M00_INI (host→DDR) and M01_INI (kernel→DDR). Update the per-SI/NSI
  `CONFIG.CONNECTIONS` so:
  - S00–S03_AXI route to **M00_INI** (+ M00_AXI for the mgmt-capable ones),
  - S00–S07_INI (SL2NOC) route to **M01_INI**.
- Connect `axi_noc_cips/M00_INI → axi_noc_ddr4/S00_INI` and
  `axi_noc_cips/M01_INI → axi_noc_ddr4/S01_INI`.
- Rationale: mirrors V80's host/kernel traffic separation; avoids one INI
  port becoming the bandwidth bottleneck and gives QoS control per class.

### A3. Wire the six known top-level connections
```
aved/LPD_AXI_NOC_0    → axi_noc_cips/S00_AXI   (clock: lpd_axi_noc_clk → aclk0)
aved/PMC_NOC_AXI_0    → axi_noc_cips/S01_AXI   (pmc_axi_noc_axi0_clk → aclk1)
aved/CPM_PCIE_NOC_0   → axi_noc_cips/S02_AXI   (cpm_pcie_noc_axi0_clk → aclk2)
aved/CPM_PCIE_NOC_1   → axi_noc_cips/S03_AXI   (cpm_pcie_noc_axi1_clk → aclk3)
axi_noc_cips/M00_AXI  → aved/s_axi_pcie_mgmt_slr0   (pl0_ref_clk domain → aclk4)
service_layer/SL2NOC_0..7 → axi_noc_cips/S00..S07_INI
service_layer/service_clk    ← cips pl2_ref_clk (250 MHz PCIe-domain clock)
service_layer/service_resetn ← clock_reset/resetn_pcie_periph
```
- Note V80 routes S00_AXI←CPM0 and S03_AXI←LPD; the SI index order doesn't
  matter as long as each SI's `CONFIG.CONNECTIONS` + clock association is
  consistent. Keep the existing FELIX aclk ASSOCIATED_BUSIF mapping.
- Check: `validate_bd_design` — remaining errors should now only concern the
  QDMA loopback and mgmt ports handled in A4/A5.

### A4. Add the QDMA slave-bridge loopback
1. Create the return NoC, exactly like V80's `static_region/axi_noc_1`:
   ```tcl
   create_bd_cell -type ip -vlnv xilinx.com:ip:axi_noc /static_region/axi_noc_qdma_ret
   set_property -dict {CONFIG.NUM_SI {0} CONFIG.NUM_MI {1} CONFIG.NUM_NSI {1} \
       CONFIG.NUM_NMI {0} CONFIG.NUM_CLKS {1}} [get_bd_cells /static_region/axi_noc_qdma_ret]
   # M00_AXI aperture must cover the CPM5 slave-bridge AXIBAR
   # (CPM_PCIE1_PF0_AXIBAR2PCIE_BASEADDR_* region, base 0x8000000000)
   ```
2. Connect: `service_layer/M_QDMA_SLV_BRIDGE → axi_noc_qdma_ret/S00_INI`,
   `axi_noc_qdma_ret/M00_AXI → aved/NOC_CPM_PCIE_0` (the CIPS slave-in
   port — currently exported as top-level port `NOC_CPM_PCIE_0_0`; re-route
   internally). Clock: `noc_cpm_pcie_axi0_clk` domain.
3. Feed the forward direction: grow `axi_noc_cips` `CONFIG.NUM_NMI` by one
   more (→3) with an INI aperture for the bridge (V80 uses a dedicated
   virt_noc stage; direct NMI is fine here) and connect
   `axi_noc_cips/M02_INI → service_layer/S_QDMA_SLV_BRIDGE`.
   Route S03_AXI (CPM_PCIE_NOC_1) to it in CONNECTIONS.
- Rationale: without this loopback the QDMA driver's slave-bridge/descriptor
  path dead-ends; it is static infrastructure, not kernel plumbing.
- Check: validate passes NoC routing for the new paths;
  `NOC_CPM_PCIE_0` no longer a floating port.

### A5. Fix the service_layer management ports
Two options — pick 1 (simpler) unless service-layer control registers are
wanted immediately:
1. **Minimal (recommended now):** delete `service_layer/S_AXILITE_INI` and
   `M_AXILITE_MGMT` pins and the internal `axi_noc_0` mgmt bridge behind
   them. Management is already fully served by
   `axi_noc_cips/M00_AXI → aved/s_axi_pcie_mgmt_slr0`.
2. **V80-faithful:** keep `S_AXILITE_INI`, feed it from a new
   `axi_noc_cips` NMI port with aperture `0x203_0000_0000 / 4M`
   (M05_INI-style), and terminate it inside service_layer on a smartconnect
   (V80 uses it for self-test/control regs). Do NOT keep `M_AXILITE_MGMT` —
   the real shell has no such port.
- Check: no unconnected AXI-Lite pins on service_layer; validate clean.

### A6. Validate + address map
- `validate_bd_design` until clean (NoC compiler will surface any remaining
  routing/aperture mistakes — fix apertures per the table in §0.1).
- `assign_bd_address`; verify against V80's map:
  - base_logic mgmt @ 0x201_0000_0000 (32M window)
  - service-layer ctrl @ 0x203_0000_0000 (if A5 option 2)
  - DDR4 @ DDR_LOW0/DDR_LOW1 (0x0 + 0x8_0000_0000 regions)
  - QDMA slave bridge AXIBAR @ 0x80_0000_0000 region (matches
    `CPM_PCIE1_PF0_AXIBAR2PCIE_BASEADDR_0`)
- Regenerate `write_bd_tcl -force` export and refresh the three
  `am_felix_*.tcl` scripts (or commit a new consolidated script) so the BD
  remains reproducible.

## Phase B — physical constraints + first bitstream

### B1. Pin constraints
- Copy DDR4 pin/bank constraints and the 200 MHz `sys_clk0` diff-clock pins
  from `felix-xpfm-project/step1_vp1552/pinout.xdc` (proven on this board).
- PCIe: GT lanes + refclk on GTYP_LPD banks 102–105 per FLX-155 schematic
  (refclk from edge connector via the Si5156 buffer). Start Gen5 **x8, Link A
  (banks 102–103)** to match the current cips config; 2×8 later if needed.
- Make external BD ports for `CH0_DDR4_0` + `sys_clk0` (the DDR pins are
  currently only implicit in `axi_noc_ddr4`).

### B2. Wrapper, synth, impl, PDI
- `make_wrapper` on `felix_cips`, add wrapper as top.
- Flat implementation first — **no DFX/BDC yet** (get hardware working
  before adding reconfiguration complexity).
- `write_device_image` → PDI.
- Checks, in order:
  1. Timing clean (or at least no inter-clock disasters on NoC/PCIe clocks).
  2. Program board; DDR4 calibration passes in boot log.
  3. `lspci -d 10ee:` shows **three functions**: 50b4 (PF0), 50b5 (PF1),
     50b6 (PF2); `lspci -vv` LnkSta = Gen5 x8.
  4. BAR peek over PF2 reaches `hw_discovery` — the driver-visible proof the
     mgmt path (S01_AXI→M00_AXI→base_logic) works.
  5. `dma-to-device`/basic QDMA transfer to a DDR4 address returns data —
     proof of the S00_AXI→DDR path.

## Phase C — DFX (after the flat shell works)

- C1. Convert `service_layer` (and, when a kernel region is defined, the
  kernel container) into Block Design Containers referencing their own .bd.
- C2. Apply `enable_dfx_bdc.tcl` logic: `CONFIG.ENABLE_DFX {true}` +
  `LOCK_PROPAGATE {true}` on each container; validate.
- C3. Define pblocks for the reconfigurable partitions; implement; generate
  the **abstract shell DCP** (this is what `v80++ link` links kernels
  against on V80 — the FELIX equivalent will be the artifact user-kernel
  builds consume).
- C4. Only after this works, consider adopting the official
  `create_project.tcl → slash_base/service_layer/top → enable_dfx_bdc`
  script pipeline with FELIX-ized copies of those files, since the real
  service_layer.tcl already supports `DCMAC0_ENABLED=0`.

## Phase D — software stack (outline)

- Kernel module + libslash port mostly as-is (they only touch the three PCIe
  PFs and QDMA queues).
- `vrtd`: stub AMI/sensor calls (`client_handle_request_get_sensor_info` →
  NOT_SUPPORTED); replace the AMI boot/reset ioctl with a direct MMIO write
  to the `pcie_mgmt_pdi_reset` GPIO (`GPIO_ALLOW_SBR`) via libslash, keep
  the PCIe hotplug SBR + rescan sequence unchanged; drop the `ami::ami`
  link dependency.
- VRT/libvrt: replace `MemoryRangeType::HBM`/`HBM_VNOC` usage with `DDR`;
  update example `config.cfg` mappings `HBM[n]` → `DDR`.
- `v80-smi`: `list`/`program`/`reset` should work once vrtd runs; sensor
  output will be empty until firmware exists.

## Phase E — firmware (outline)

- AMC (RPU firmware) is the least portable piece — built around V80
  sensors/QSFP/SMBus profiles.
- **First light needs no firmware at all**: the `gcq_m2r` command queue
  simply stays idle; host-side tooling that doesn't query sensors works.
- Later: write a minimal FELIX AMC profile — I2C (INA226 @0x40/0x41 power
  monitors, ADM1266 sequencer), fan on LPD_MIO21/22 — reusing AMC's
  profile/FAL abstraction. Optionally add an `axi_iic` on `rpu_sc/M01_AXI`
  (the slot V80's SMBus occupied; the top-level `smbus_0` port was `iic_rtl`
  typed anyway, so AMI-style tooling stays drop-in-shaped).
